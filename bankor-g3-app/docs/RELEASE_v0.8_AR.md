# إصدار Bankor G3 Academy v0.8 — تحسين الثبات وتجهيز أول مسار APK

## التغييرات المنفذة في المصدر

1. **سلسلة المذاكرة الفعلية (Activity Streak):** تُحتسب من الأيام التي اكتمل فيها درس أو اختبار بأسئلة فعلية، بدل اقتصارها على الدروس؛ يستمر عداد الأمس ظاهرًا حتى تبدأ جلسة اليوم، دون منح نقاط وهمية.
2. **حماية إتمام الاختبار مرتين:** إضافة حارس في الواجهة ضد السباق بين زر التسليم والمؤقت، ومعرّف ثابت لكل جلسة اختبار يجعل تسجيل النتيجة والمكافآت idempotent في محرك الاختبار.
3. **رسالة متابعة في الرئيسية:** عند عدم تسجيل نشاط تعليمي لليوم يظهر تشجيع خفيف من بنكور لفتح تدريب قصير.
4. **فحص سلامة المحتوى:** 113 درسًا و895 سؤالًا، بدون أخطاء في فهارس الإجابة أو روابط أسئلة الدروس، وحصص المحاكاة مكتملة. تم رصد أسئلة لموضوع `camunda` بلا درس مستقل، ولا توجد مادة علمية مخترعة لسد الفجوة.
5. **GitHub Actions لعمل APK تجريبي:** إضافة `.github/workflows/android-debug-apk.yml`. تشغيل يدوي بعد رفع المشروع إلى مستودع GitHub، ويتحقق من المحتوى والاختبارات وTypeScript ثم يجرب Android Debug Build ويرفعه كـ Artifact إذا نجح. هذا المسار **أُعد ولم يُشغّل**.
6. **فحوص إضافية:** اختبار `activity.test.cjs`، اختبار منع تكرار نتائج الجلسة، تدقيق المحتوى، وفحص صياغة ملفات TSX.

## التحقق المنفذ في بيئة العمل

- `npm test`: **نجح**، بما فيه 7 ملفات اختبار + تدقيق المحتوى + فحص صياغة المصادر.
- ملف Workflow: **صياغة YAML صحيحة** في فحص محلي.
- التحقق من توافق React 19.3 / React Native 0.88 / Expo SDK 58 ومن وجود مكتبة تغيير الأيقونة تم بالمراجع العامة.

## غير المنفذ

- `npm install` لم ينجح في بيئة العمل بسبب فشل DNS إلى npm (`EAI_AGAIN`).
- `npm run check` فحص الأنواع للمشروع الكامل غير متاح دون تثبيت الحزم.
- `expo prebuild` وGradle وAndroid runtime لم يتم تشغيلهم فعليًا.
- لا يوجد APK أو AAB جاهز؛ لا ادعاء بأن Workflow أو الأيقونة الديناميكية اختُبرا على هاتف.

## خطوات إخراج APK عبر GitHub (بدون حساب Expo)

1. ارفع محتويات مجلد المشروع بالكامل إلى مستودع GitHub **جديد أو فرع مخصص** (ليس مجرد ملف ZIP، ولا ترفع محتويات المشروع القديم فوق ملفات الويب بلا مراجعة).
2. افتح تبويب **Actions** في المستودع، ثم اختر **Build Bankor Android APK** → **Run workflow**.
3. إذا نجح البناء، افتح تشغيل Workflow ثم **Artifacts** وحمّل `bankor-g3-v0.8-debug-apk`، وفك الضغط لتجد `app-debug.apk`.
4. انقل APK لهاتف Android وثبّته لأغراض الاختبار فقط، وقد يطلب الهاتف السماح بالتثبيت من المصدر المستخدم.
5. إذا فشل CI، ارجع إلى خطوة الفشل في سجل Actions. قد تحتاج إلى تحديث إصدار مكتبة أو إعداد Native plugin قبل إعادة المحاولة.

> Debug APK تجريبي وغير مهيأ للنشر على Google Play. للإصدار النهائي يُحتاج build release موقّع مع اختبارات فعلية.

## خصوصية وسلامة التقدم

بيانات التقدم محفوظة محليًا في AsyncStorage داخل الجهاز. **حذف التطبيق يمكن أن يمحو التقدم نهائيًا**؛ لم تُنفّذ خاصية النسخ الاحتياطي/المزامنة بعد. المحتوى الدراسي غير معتمد رسميًا ويحتاج مراجعة علمية قبل أي استخدام مهني.
